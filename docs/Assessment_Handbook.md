## Capstone Project: Data Analytics with AI

### Project Purpose

Students must build a data application with user interface combining Python packages for data analysis, visualization, and Streamlit. The project requires critical data analysis to generate insights and deliver data-driven recommendations aligned with professional business requirements.

### Main Technologies

**Required:** Python and related libraries for data analysis tasks covered in the course. Only Python is permitted as the programming language.

### Project Ideas

#### Project Idea 0: Custom Concept

Develop original ideas addressing real or imagined needs. Dataset must answer business case requirements. If not clearly public domain, obtain owner permission before hosting in public repositories. Data must be anonymized to protect privacy.

#### Project Idea 1: Climate Change and Environmental Sustainability

Focus areas include carbon footprint analysis, renewable energy, wildlife conservation, pollution monitoring, or sustainable urban development.

**Requirements:**
- Environmental data analysis using climate and biodiversity datasets
- Predictive modeling for environmental changes
- Impactful data visualizations
- Real-time sensor/IoT data integration
- Public awareness tools
- Collaboration with environmental organizations

#### Project Idea 2: Healthcare and Public Health

Explore disease prediction, telemedicine, resource optimization, and patient data analysis.

**Requirements:**
- Health data analysis considering privacy and ethics
- Predictive models for health outcomes
- Epidemiological data study
- Medical imaging analysis using deep learning
- Patient care optimization tools
- Collaboration with medical professionals

## Critical Project Requirements

**IMPORTANT:** All pass criteria must be achieved for passing grade.

### Functionality and Design Requirements

The finished project must:

1. **Clear Purpose:** Demonstrate well-defined purpose addressing target audience(s). Purpose should be immediately evident without supporting documentation.

2. **Professional Dashboard:** Fully functioning, well-documented web dashboard for real-life audience following UX design principles and accessibility guidelines with complete responsiveness.

3. **Code Quality:** Well-organized, easy-to-follow code with clear development process evidenced through commit messages.

4. **Comprehensive Documentation:** Clear, justified rationale for real-world application with complete explanation of development approach.

5. **Publishable Standard:** Judged suitable for publication showing professional-grade interface adhering to current practice with no obvious code errors.

6. **Craftsmanship:** Original application demonstrating code characteristics and not copying course walkthroughs.

7. **Hypothesis Validation:** Must elaborate and validate hypotheses from "Project Hypothesis" section in README.

8. **Visualization Requirements:** Display at least four different plot types in dashboard, each addressing business requirements.

9. **Version Control:** Code demonstrates files pushed to repository are stored under dedicated folders relating to project version.

### Design Principles

#### Information Hierarchy
- Semantic markup conveys structure
- Organized, easily-findable information
- Resources categorized by priority

#### User Control
- Positive emotional user responses through flow, color, navigation
- No aggressive auto-popups or autoplay; user-initiated actions

#### Consistency
- Evident across all pages/sections and interactivity

#### Confirmation
- User and data actions confirmed with feedback

#### Accessibility
- Conform to accessibility guidelines across pages and interactivity

### Development and Implementation Standards

#### Code Characteristics
- Demonstrates "clean code" qualities
- Consistent, descriptive naming conventions
- Clear file separation (custom code vs. external files)
- Comments explaining code segment purposes
- No logic errors on execution
- Full design implementation meeting user demands

#### Real-World Application
- Site-specific content (no Lorem Ipsum)
- External links open in separate tabs
- Custom video content fit for purpose

#### Version Control Practices
- All code in git with meaningful commit messages
- Separate, well-defined commits per feature/fix
- No excessively large commits

#### Documentation
- README clearly describes purpose, goals, target audience
- Development process evident throughout

## Plagiarism Policy

### Definition and Consequences

Plagiarism is "_the practice of taking someone else's work or ideas and passing them off as one's own_" (Oxford Dictionary). It is a serious academic offense with serious consequences.

### Acceptable Practices

- Using and referencing others' code is acceptable
- All non-original work must be correctly referenced and acknowledged
- Projects undergo plagiarism review including code comparison tools, plagiarism software, git history review, and other mechanisms

### Student Responsibility

Students must ensure complete and adequate acknowledgment of all included work from others. Plagiarism may be unintentional but remains an offense.

### Attribution Requirements

- All sources must be attributed
- Any code not student-written requires explicit credit
- Failure to properly credit others' code results in failing grade
- Blatant or repeat offenses result in stringent penalties including course removal

**Guidance:** When in doubt, include attribution. Consult facilitation team for plagiarism-related questions.
